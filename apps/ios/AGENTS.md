# AGENTS.md

This is the independent SwiftUI iPhone app, targeting iOS 26 and later. Use native Liquid Glass for chrome and composer surfaces, while respecting Reduce Transparency. Do not add older-iOS material fallbacks. Do not modify `apps/mobile` to implement native iOS features.

- `Sources/MainsCore` owns the portable wire codec, DTOs, pairing client, socket ownership, bounded history projection and backend session. It compiles as a Swift package on macOS for tests and directly into the iOS app.
- `Sources/MainsApp` owns SwiftUI screens, camera scanning, Keychain and filesystem adapters. Keep network behavior out of views.
- `packages/contracts/src` remains the source of truth for channel names, payloads, date/undefined tags, command receipts and transcript behavior. Swift models cover the subset used by this client. Changes to the shared wire protocol need explicit coordination with other clients.
- The credential belongs only in this app's Keychain service. Disposable cache files never contain tokens or live stream previews.
- Retain a mutation's original command ID, payload, computer and total deadline during reconnection. Only connection loss automatically retries. Unknown receipt outcomes block fresh sends and retain the original identity for an explicit delivery check.
- Running local Codex and Claude conversations always queue new input, with per-row Steer/edit/remove/reorder actions. Show the queue only when it has messages; do not show an empty Queue bar or a delivery-mode selector. The session owns FIFO consumption across navigation; only a confirmed successful turn releases automatic continuations. Stop, failure, background and connection changes pause until explicit Resume. Keep message files/context/settings and an editing draft backup in bounded memory, outside snapshots. Settings edits for queued input stay local. Unknown deliveries retain commandId/clientUserMessageId and the frozen input for inputStatus/original-receipt checks; never resend or retire them through history alone. Queue-owned messages create no optimistic transcript rows and do not move the reader.
- Fence asynchronous writers by pairing ownership, transport generation and viewed conversation. History is one bounded `profile: mobile` page; do not append entire histories or tool outputs.
- Desktop queues are a read-only, leased display projection (`runs:getQueue`/`runs:queueChanged`), separate from the phone's delivery queue. Their originating renderer remains the sole consumer; never re-enqueue remote rows, copy upload identities/settings or persist projections. Clear them on navigation/connection ownership changes and discard expired snapshots. Photo authorization must survive temporary scene inactivity; cancelled loads must retire loading, and media fallbacks/controls must fill the panel bounds.
- Native iOS supports the sidebar, shared home/conversation composer, durable conversation model/permission settings, bounded file/photo attachments, grouped tool calls with bounded output/diff previews, inline conversation images, document cards native file/PDF previews up to 25 MB, and fully on-device Demo Mode. Demo keeps mutations and imported files in memory, uses a separate launch flag, and never changes real pairing credentials, cache or provider consents. Tool approvals, option/custom/secret user questions, flat MCP forms and URL requests, and Codex async questions are supported. Pending decisions and form drafts stay in memory and are fenced by request token, run and backend. Unconfirmed approvals retain their answer and receipt; async answers reconcile with checkOnly. Native Markdown includes GFM tables, task lists, nested quotes, headings, lists, inline formatting and fenced code. Mathematical typesetting and raw HTML remain later work. Surface these limits accurately.
- Plugin/skill/command context uses lazy provider/workspace-scoped catalogue reads and refreshes on skillsUpdated. Keep catalogues and draft selections in memory, retain context in the original send receipt, and drop selections after provider/workspace changes. Render selected context as atomic inline tokens in the editable text and sent prompts, with accessible readable labels; preserve Unicode/caret positions and keep undo fenced to the provider/workspace. Match the React Native mention/command contract; never open computer-local skill/icon paths on the phone.
- Transcript history keeps one bounded window. Match desktop’s directional edge paging, preserve visible row offsets across overlapping pages, and keep Jump to latest separate from reading. Paused live-follow is distinct from explicit historical navigation; background refresh, keyboard changes and content growth must never trigger paging or steal the reader’s position. A failed or retired request cannot resume following.
- Keep live chat layout stable: one scroll controller, eager measurement inside the bounded page, one parent list for each message through streaming/finalization, and stable optimistic-to-durable prompt identity. Observed work stays expanded after completion until the user collapses it; reopened history starts compact. Image preview frames stay fixed while loading and offscreen images release decoded content.
- Running indicators follow foreground tool lifecycle and provider thinking snapshots. Keep live thoughts bounded in memory and outside transcript prose/cache; clear them on completion, stream retirement and reconnection. Hide redundant indicators while assistant text streams or the active tool row is visible. Provider-coloured loader/shimmer animations respect Reduce Motion and inactive scenes.
- Subagents are a read-only projection of the loaded mobile history window. A stable capsule above the composer opens an overlay list without resizing the transcript; agent sheets show anchored child tools/messages, tasks and reports. Fold continuation executions by native agent identity and respect provider lifecycle, background idle states and parent links. Keep at most four child message previews of 8,192 characters each in memory; acknowledge them by stream ID, preserve their first date, and clear them on stream retirement. Never fetch a whole conversation/tool catalogue to populate this UI or expose child output in the main transcript. Demo includes prepared working/completed Security and Tests agents.
- Completed Code/Work turns expose read-only changed-file summaries and paged per-file diffs. Read stored patches only through the run/turn-scoped `turn-diff` history-content channel; do not read host paths or persist full patches. Keep one bounded numbered page, Unicode-scalar cursors, and ownership/connection/conversation fences. Diff navigation must preserve the conversation's reading position. Demo supplies only prepared in-memory changes.

Run from `apps/ios`:

```sh
swift test
xcodebuild -project Mains.xcodeproj -scheme Mains -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

See README.md for fixture integration/UI tests. The committed Xcode project has no third-party runtime dependencies. After adding/removing Swift files, regenerate it with `ruby scripts/generate-project.rb` (requires the `xcodeproj` gem), or update its groups/build phases in Xcode.
