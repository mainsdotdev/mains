# AGENTS.md

This is the independent SwiftUI iPhone app, targeting iOS 26 and later. Use native Liquid Glass for chrome and composer surfaces, while respecting Reduce Transparency. Do not add older-iOS material fallbacks. Do not modify `apps/mobile` to implement native iOS features.

- `Sources/MainsCore` owns the portable wire codec, DTOs, pairing client, socket ownership, bounded history projection and backend session. It compiles as a Swift package on macOS for tests and directly into the iOS app.
- `Sources/MainsApp` owns SwiftUI screens, camera scanning, Keychain and filesystem adapters. Keep network behavior out of views.
- `packages/contracts/src` remains the source of truth for channel names, payloads, date/undefined tags, command receipts and transcript behavior. Swift models cover the subset used by this client. Changes to the shared wire protocol need explicit coordination with other clients.
- The credential belongs only in this app's Keychain service. Disposable cache files never contain tokens or live stream previews.
- Unsent home/conversation text persists separately in protected, atomic Application Support files, scoped by backend/device and space/run. Keep only text (512 KB each, 128 drafts/8 MB per pairing), remove it on send and pairing retirement, preserve newer input, and restore on definite refusal. Queue edits cannot overwrite the normal saved draft; queues/files/context/backups/receipts remain memory-only. Demo must never access real saved drafts.
- Account-wide conversation/title/message search uses bounded, paginated `search:conversations`, not the broader `search:query` host projection. Keep excerpts and artifact cursors small, reject stale ownership/connection/query responses, and open matches through the existing mobile history window without downloading full transcripts. Retain an older viewed run outside the recent 100 descriptors; offline/unsupported search explicitly shows the saved subset.
- Sidebar Activity is an independent, bounded, memory-only projection across providers/spaces. Use runs:listActive for authoritative live work, runs:listPendingApprovals for request identities/expiry, runs:getAll for recent descriptors and bounded runs:getById reads for older requested chats. Never load histories or change the selected transcript to populate it. Retain at most 100 runs/200 request identities; request evidence and answers stay in the existing conversation reader. Poll only while the sidebar/inbox is visible, fence reads by pairing/connection/request revision, and hide decisions/disable Stop on stale or offline views. Stop uses the existing receipt-backed abort path; replicas stay read-only. Demo stays in memory.
- Sidebar Atlas reads the account library independently of the selected provider/mode. Read through atlas:mobileLibrary, atlas:readMobilePage, atlas:describeMobileFile and atlas:readMobileFile; broad Atlas APIs and computer paths stay private. Keep one 50-entry filtered library page and one 16,384-Unicode-scalar Markdown part in memory, outside snapshots. Page reads pin their version; refresh restarts at the beginning. Explicitly saved items remain visible across modes, while automatic uploads/outputs come only from Work conversations. Stream version-checked files in 128 KB chunks up to 100 MB into protected temporary files and remove partial/closed downloads. Fence reads/downloads by pairing and connection; filter changes cancel older reads. Opening Atlas never changes Space mode or loads transcripts. Page blocks remain canonical on the computer; phone Markdown is display-only. Embedded Atlas files open by identity; arbitrary host links stay blocked. Demo is prepared in-memory content, and older computers show an update message.
- Atlas list thumbnails use atlas:readMobileImage with existing file identities, capped at 128 pixels and 128 KB. Recheck account, active membership/Trash and version after decoding, including cache hits and replica readers. Request only visible rows and release decoded images offscreen; failures/older computers retain category icons. Optional library metadata contains only a filename, MIME type, byte size and at most 240 Unicode scalars of display-only Page preview, never paths or embedded-file hydration. Show bookmark hosts and file type/size instead of redundant source labels. Demo thumbnails are prepared sample bytes, kept in memory.
- Atlas saves use only receipt-backed atlas:saveMobileFile and atlas:saveMobileBookmark commands. Save files by exactly one conversation artifact, attachment or generated source identity plus its described version; never send paths or re-upload preview bytes. The computer rechecks account, local ownership, selected output/attachment membership and version before retaining an immutable snapshot. Replicas save from their source computer. Bookmark creation accepts a web URL and optional account-owned project, preserving canonical URL deduplication and existing authored fields. Keep one pending Atlas write in memory across navigation/reconnects, freeze its payload/command ID, block new Atlas saves while uncertain, and expose Check save outside its original sheet. Definite refusal releases admission; pairing retirement clears state and late results cannot populate another pairing. Demo saves and receipts stay in memory.
- Atlas organization uses only receipt-backed atlas:updateMobileItem, with explicit isFavorite and/or collectionId values (null removes the project). Target the permanent savedIdentity, including savedItemId/savedCollectionId on generated projections; never move a source conversation or create an implicit saved copy. The computer rejects Trash, foreign/archived projects and all other patch fields, and rechecks active ownership after project validation. Reuse the single pending Atlas write and Check change recovery, validating the echoed requested identity and fields. Refresh filtered library reads after confirmation; never apply a recovered receipt over newer metadata. Page content, file bytes and source context stay unchanged.
- Bookmark editing uses atlas:readMobileBookmark for a fresh bounded title/description/note snapshot and opaque revision, then receipt-backed atlas:editMobileBookmark with only dirty fields. Title is required (240 UTF-16 units); description/note allow empty strings and are capped at 2,000/10,000 units. URL, project, favorites, tags and broad Atlas fields remain outside this edit command. Validate the account/kind/Trash state and recheck the editable-content revision at the bookmark worker's synchronous commit seam after async preparation. Unrelated organization changes do not invalidate the content revision. Keep drafts in memory without auto-reloading over them; stale saves refuse and an explicit reload discards edits. Reuse the shared Atlas receipt owner/Check change recovery, and refetch after acknowledgement rather than applying old receipt content.
- Atlas Trash uses atlas:mobileTrash for one path/content-free 50-item page and receipt-backed atlas:setMobileTrash with only the permanent id and explicit trashed boolean. Repeated state changes are idempotent; repeated Trash preserves its original date. Only saved items support Trash. Restore preserves Page versions, file bytes, bookmark fields, project/favorite metadata and source conversations; permanent deletion remains unavailable. Reuse the shared pending Atlas write and Check change recovery, then refetch current state rather than applying an older receipt. Fence Trash reads by pairing/connection/revision; an emptied later page resets to page one. Demo stays in memory.
- Atlas tags use atlas:mobileTags for a searchable 50-tag catalogue page, atlas:readMobileTags for a fresh saved-item tag selection/revision, and receipt-backed atlas:setMobileTags for only tags plus the expected revision. Reuse desktop tag identities, NFKC/name deduplication, 30-selection/64-UTF-16-input limits and user exclusions against automatic tagging. Show at most 60 tags per library entry; larger merged selections need desktop editing. Tag revisions cover identities/names/provenance, excluding unrelated content/project/favorite changes, and are checked synchronously with the transactional writer. Keep edit drafts in memory and reload only explicitly after a conflict. Share the Atlas pending-write owner/Check change recovery; refresh current data after acknowledgement. Tag filters reset library pagination, catalogue search keeps one page, and stale pairing/connection/query reads cannot publish. Demo remains in memory.
- Retain a mutation's original command ID, payload, computer and total deadline during reconnection. Only connection loss automatically retries. Unknown receipt outcomes block fresh sends and retain the original identity for an explicit delivery check.
- Running local Codex and Claude conversations always queue new input, with per-row Steer/edit/remove/reorder actions. Show the queue only when it has messages; do not show an empty Queue bar or a delivery-mode selector. The session owns FIFO consumption across navigation; only a confirmed successful turn releases automatic continuations. Stop, failure, background and connection changes pause until explicit Resume. Keep message files/context/settings and an editing draft backup in bounded memory, outside snapshots. Settings edits for queued input stay local. Unknown deliveries retain commandId/clientUserMessageId and the frozen input for inputStatus/original-receipt checks; never resend or retire them through history alone. Queue-owned messages create no optimistic transcript rows and do not move the reader.
- Fence asynchronous writers by pairing ownership, transport generation and viewed conversation. Native history requests `profile: mobile` with `conversationWindow: true`: desktop's 20-prompt/60-block boundaries with at most 200 preview rows/about 1 MB. Prioritize prompts and each block's last visible reply so hidden child activity cannot evict the dialogue. Omitted messages/tools open in a separate, bounded activity reader using the returned frozen range; it never replaces or appends to the main transcript and never follows outside that range. Legacy mobile row paging remains unchanged.
- Desktop queues are a read-only, leased display projection (`runs:getQueue`/`runs:queueChanged`), separate from the phone's delivery queue. Their originating renderer remains the sole consumer; never re-enqueue remote rows, copy upload identities/settings or persist projections. Clear them on navigation/connection ownership changes and discard expired snapshots. Photo authorization must survive temporary scene inactivity; cancelled loads must retire loading, and media fallbacks/controls must fill the panel bounds.
- Forking uses the existing `runs:fork` command with sourceRunId/accountId and the desktop's default continuation message. The backend inherits the provider session/settings; never construct a branch by copying transcript rows or transferring a draft/queue. Offer it from the latest settled response and conversation menu, disabled for running/offline/replica sources or unresolved deliveries. Keep an unconfirmed fork's original payload/command identity in memory, expose recovery outside its source screen, and block fresh sends until resolved. A late acknowledgement cannot change a replacement pairing or navigate away from a different viewed conversation. Demo forks are receipt-backed in-memory samples.
- Native iOS supports the sidebar, shared home/conversation composer, durable conversation model/permission settings, bounded file/photo attachments, grouped tool calls with bounded output/diff previews, inline conversation images, document cards, streamed file downloads up to 100 MB, paged UTF-8 text/Markdown and native file/PDF previews, and fully on-device Demo Mode. Demo keeps mutations and imported files in memory, uses a separate launch flag, and never changes real pairing credentials, cache or provider consents. Tool approvals, option/custom/secret user questions, flat MCP forms and URL requests, and Codex async questions are supported. Pending decisions and form drafts stay in memory and are fenced by request token, run and backend. Unconfirmed approvals retain their answer and receipt; async answers reconcile with checkOnly. Native Markdown includes GFM tables, task lists, nested quotes, headings, lists, inline formatting and fenced code. Inline/display LaTeX uses bundled KaTeX in an isolated offline WebKit surface; raw HTML stays escaped. Surface these limits accurately.
- Plugin/skill/command context uses lazy provider/workspace-scoped catalogue reads and refreshes on skillsUpdated. Keep catalogues and draft selections in memory, retain context in the original send receipt, and drop selections after provider/workspace changes. Render selected context as atomic inline tokens in the editable text and sent prompts, with accessible readable labels; preserve Unicode/caret positions and keep undo fenced to the provider/workspace. Match the React Native mention/command contract; never open computer-local skill/icon paths on the phone.
- Transcript history keeps one bounded window. Match desktop’s directional edge paging, preserve visible row offsets across overlapping pages, and keep Jump to latest separate from reading. Paused live-follow is distinct from explicit historical navigation; background refresh, keyboard changes and content growth must never trigger paging or steal the reader’s position. A failed or retired request cannot resume following.
- The adaptive conversation workspace keeps one stable conversation/preview layout tree. Use local geometry/size classes and iOS 27.1+ reserved division regions, not device names, screen globals, rotation callbacks or hinge-angle thresholds. Book folds separate readers horizontally; tabletop folds place outputs above the composer/chat. Narrow windows and accessibility text show the last focused reader while retaining both view identities, selected file/version and viewport; explicit closure removes preview bytes. Keep the Home sidebar bounded/collapsible and never replace the navigation root while resizing. Output panes use existing bounded session readers and protected temporary downloads, never host paths; metadata refreshes cannot silently replace a pinned preview. Hide inactive panes from accessibility/hit testing, release hidden chat thumbnails and interrupt hidden gestures without changing follow intent. Layout changes never select a conversation, restart transport or send input. Single-scene ownership remains unchanged. Demo follows the same UI with prepared files.
- Keep live chat layout stable: one scroll controller, eager measurement inside the bounded page, one parent list for each message through streaming/finalization, and stable optimistic-to-durable prompt identity. Observed work stays expanded after completion until the user collapses it; reopened history starts compact. Image preview frames stay fixed while loading and offscreen images release decoded content.
- Running indicators follow foreground tool lifecycle and provider thinking snapshots. Keep live thoughts bounded in memory and outside transcript prose/cache; clear them on completion, stream retirement and reconnection. Hide redundant indicators while assistant text streams or the active tool row is visible. Provider-coloured loader/shimmer animations respect Reduce Motion and inactive scenes.
- Match desktop's stable work-summary phrases and display-only stale-tool projection across rows, groups and the activity footer. Later foreground output retires earlier running/queued previews; the trailing parallel batch stays live. Thinking, tool progress and child activity cannot settle foreground tools, and explicit background MCP task lifecycle wins. Never write inferred display completion into wire history or cache. Timestamp ties sort artifacts before tools, then numeric source ids.
- Subagents are a read-only projection of the loaded mobile history window. A stable capsule above the composer opens an overlay list without resizing the transcript; agent sheets show anchored child tools/messages, tasks and reports. Fold continuation executions by native agent identity and respect provider lifecycle, background idle states and parent links. Keep at most four child message previews of 8,192 characters each in memory; acknowledge them by stream ID, preserve their first date, and clear them on stream retirement. Never fetch a whole conversation/tool catalogue to populate this UI or expose child output in the main transcript. Demo includes prepared working/completed Security and Tests agents.
- Resolve local message/document links through run-scoped output descriptors; Work/Chat Markdown may fall back to runs:readTextFile. Never open computer paths on iOS or grant general filesystem access. Stream version-checked 128 KB chunks to protected temporary files, remove partial/closed files, and page UTF-8 text without splitting scalars. Unknown formats remain downloadable/shareable. Math uses Resources/Math (KaTeX JS/CSS/fonts plus license), with escaped application-generated HTML, trust disabled, expansion/size limits, nonpersistent WebKit state, CSP network blocking and navigation/message identity fences. Preserve code/currency and keep a readable fallback for malformed/oversized math. No remote scripts, fonts or images.
- Completed Code/Work turns expose read-only changed-file summaries and paged per-file diffs. Read stored patches only through the run/turn-scoped `turn-diff` history-content channel; do not read host paths or persist full patches. Keep one bounded numbered page, Unicode-scalar cursors, and ownership/connection/conversation fences. Diff navigation must preserve the conversation's reading position. Demo supplies only prepared in-memory changes.

- Native GPT Live uses the existing Codex v3 WebRTC backend and its ChatGPT authentication. MainsCore owns the app-scoped call, original connection/receipt identities and bounded transcript/context projection; MainsApp owns WebRTC tracks, AVAudioSession and SwiftUI controls. Keep audio off the Mains socket, use native session.context.append (500-byte UTF-8 chunks), and never replay an SDP offer on a new peer. Navigation and temporary inactivity preserve the call; active background audio keeps its control socket alive while queues pause. Stop releases the mic immediately and retains failed native closure for retry. Only final speech enters normal history/cache; work completion cannot settle speech, and provenance hides only duplicate voice-work narration. Demo never opens a microphone or a live call. Voice display defaults to Focus (centered water orb, hidden transcript, compact controls); Conversation puts the larger orb outside and above the normal composer. Switching is a local preference and must preserve the same call, mute state and transcript viewport. Keep VoiceWater.metal in the app source build phase; its audio envelope is view-local, drawing pauses offscreen/inactive and Reduce Motion freezes the shader. Debug voice previews use in-memory storage/media and a separate preferences suite only.

Settings → GPT Live → Voice owns voice selection and previews; the in-call sliders menu changes display only. Voice selection reads the live Codex catalog and saves only `realtimeVoice` through receipt-backed `providers:updateRunSettings`; it shares the desktop preference and applies to the next voice session. Keep the voice outside conversation model snapshots. Unconfirmed saves retain their original identity and block fresh selections/new voice calls until checked. Bundled VoicePreviews are local playback only; samples without recordings stay selectable, previews stop offscreen/inactive and never play into an active call. Demo edits stay in memory.

- Conversation menu actions use the existing receipt-backed `runs:moveToCollection` (Work/Chat only), `runs:archive` and `runs:delete` (all modes). Keep original command arguments/id in one memory-only pending action across navigation/reconnects, block competing sends/queue consumption, and expose Check change outside the original menu/sheet. Refuse replicas, offline/active retirement and unsettled delivery/settings/decision state. Project moves preserve the same run, draft, history and selected space; read current membership after acknowledgement instead of applying a replayed row. Confirm permanent deletion, clear only that chat's local history/queue/draft after acknowledgement, preserve archived drafts, fence stale metadata reads and remove only matching navigation routes. Demo mutates in-memory fixtures and receipts only.

- Developer hot reload uses the local InjectionIII helper only in Debug simulators. Keep `DeveloperHotReload.swift` and each view/modifier's `@ObserveHotReload` under `#if DEBUG && targetEnvironment(simulator)`. New SwiftUI views should observe it as well; Xcode's Debug opaque-type erasure handles body changes. Never reset view/session identity to refresh UI. Keep interposition/compiler-log/cache settings qualified to Debug + iphonesimulator, exclude the runtime source from Release, disable it in UI-test app launches, and never embed injection bundles or add device permissions. `npm run dev:hot-reload` installs the pinned helper on the developer's Mac; the portable core stays dependency-free.

- Atlas Page headers display the stored cover edge to edge with an optional overlapping icon; coverless/iconless pages keep a compact title layout. `atlas:readMobilePage` exposes only an optional cover identity. `atlas:readMobilePageCover` returns a Page-bound image derivative up to 768 pixels/512 KiB, rechecking the current cover, account, Trash and file version after decoding/hydration. Cover bytes stay view-local, release offscreen and cannot cross connection/pairing ownership. Older computers omit the cover field and remain readable. The native options button is reserved for future actions; pull to refresh retains the existing reader/version reset.

- Pass an explicit `alignment: .center` to SwiftUI's closure-based `.background(alignment:content:)`. Debug hot reload can promote the imported default-argument thunk to a strong symbol in multiple object files, breaking the next incremental link. Explicit alignment keeps that shared thunk out of the objects without disabling injection or changing view layout. This does not apply to UIKit's `UIHostingConfiguration.background` API.

- Atlas Page body images stay in their Markdown position through `AtlasPageSection`; preserve the remaining Markdown verbatim for math/tables and never turn code examples or local/remote URLs into automatic image reads. `atlas:readMobilePageImage` accepts only a Page id, pinned version and stored file id, verifies canonical image-block membership and active account/file state before and after bounded decoding/hydration, and returns at most 768 pixels/512 KiB. Keep a fixed preview frame while bytes arrive, load only visible images, release them offscreen and fence connection/pairing results. Tapping opens the existing protected Atlas file preview; non-image files retain their existing footer links. Demo media stays prepared and in memory.

- Page-uploaded files remain readable stored assets but stay out of the Atlas library until explicitly saved. `AtlasFile.canSaveToLibrary` enables Save to Atlas in the existing file preview. The receipt-backed `atlas:saveMobileFile` accepts an exclusive stored `itemId` plus file version to promote the same identity; keep conversation source identities mutually exclusive and preserve pending-write recovery. Older hosts omit this capability.

- Markdown tables measure styled SwiftUI cells, including semibold headings and Dynamic Type, through `MarkdownTableGrid`. Keep one shared column plan and uniform row bounds, fill the available width for short tables and retain horizontal scrolling for wider content. Do not return to raw-string/regular-UIFont estimates or paint a viewport-wide card behind a narrower header. Math tables use semantic `thead`/`tbody`, normal word wrapping and noncollapsed empty cells; keep both renderers aligned.
